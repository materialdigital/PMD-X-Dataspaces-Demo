The integration problem

Catena-X and Manufacturing-X each expose material data through their own schemas — SAMM (Semantic Aspect Meta Model) aspect models for polymer properties, AAS (Asset Administration Shell) 3.0 inspection documents for steel certifications. A conventional integration requires a bespoke adapter for every pair of schemas.

The PMD approach is different: each dataspace's data is converted once into PMDCO (PMD Core Ontology)-conformant RDF, loaded into a shared triplestore, and from that point forward is queryable together using SPARQL — regardless of the original format.

The Tension Pulley Assembly demonstrates this: one physical part, two components sourced from incompatible dataspaces, unified by a single cross-dataspace SPARQL UNION query.

Without PMDCO

CatX ──adapter──► …

Catena-X — PA6GF30 Material Data

The source is a SAMM (Semantic Aspect Meta Model) aspect model for glass-fiber polyamide (PA6GF30) retrieved via Eclipse Dataspace Connector (EDC); the schema is Catena-X proprietary and not interoperable with Manufacturing-X out of the box.

{
  "materialInformation": {
    "materialName": "PA6GF30",
    "materialIdentifier": "Z1234"
  },
  "mechanicalProperty": {
    "impactStrength": 74,
    "youngsModulus": 9800,
    "strainAtBreak": 3,
    "stressAtBreak": 140,
    "flexuralStrength": 210,
    "flexuralModulus": 8600
  },
  "thermophysicalProperty": {
    "meltingTemperature": 223,
    "waterAbsorption": 6.5
  },
  "physicalProperty": {
    "density": 1530
  }
}
Schema challenge: field names like stressAtBreak are Catena-X SAMM-specific. No shared unit annotation. No ontology link.

Manufacturing-X — Steel 316/4401 Inspection Document

The source is an AAS (Asset Administration Shell) 3.0 inspection certificate for cold-rolled stainless steel following EN 10204; the structure is fundamentally different from the Catena-X SAMM schema — a different ontology, different property naming, different unit representation.

Mapping to PMDCO — Common Semantic Ground

Each dataspace's data is converted independently to PMDCO-conformant RDF: for Catena-X this uses YARRRML + RDFConverter + a SPARQL INSERT; for Manufacturing-X the AAS2KG tool produces RDF, then a SPARQL CONSTRUCT maps to PMDCO qualities and QUDT units.

# pmdco-mapping-insert.sparql (key clauses)
PREFIX mat:   <urn:samm:io.catenax.material_data:1.0.0#>
PREFIX qudt:  <https://qudt.org/schema/qudt/>
PREFIX unit:  <https://qudt.org/vocab/unit/>
PREFIX obo:   <http://purl.obolibrary.org/obo/>
PREFIX pmd:   <https://w3id.org/pmd/co/>

INSERT { GRAPH <pmdco> {
  ?quality a              ?qualityClass ;
           obo:IAO_0000417 ?datum .
  ?datum   obo:OBI_0001938  ?qv .
  ?qv      qudt:unit          ?qdtUnit ;
           qudt:numericValue  ?convertedValue .
} }
WHERE {
  /* SAMM unit → QUDT unit + SI factor */
  VALUES (?sammUnit ?qdtUnit ?factor) {
    ( sunit:megapascal   unit:MegaPA   1 )
    ( mat:kiloJoulePerSquareMeter   unit:J-PER-M2  1000 )
  }
  /* SAMM property → PMDco quality class */
  VALUES (?prop ?qualityClass) {
    ( mat:stressAtBreak   pmd:PMD_0000952 )
    ( mat:youngsModulus   pmd:PMD_0000618 )
    ( mat:impactStrength  pmd:PMD_0000518 )
    ( mat:meltingTemperature pmd:PMD_0000851 )
  }
}
# InspectionDocument_AAS2KG_mapping.sparql (key clauses)
PREFIX aas:  <https://admin-shell.io/aas/3/0/>
PREFIX tto:  <https://w3id.org/pmd/tto/>
PREFIX pmd:  <https://w3id.org/pmd/co/>
PREFIX obo:  <http://purl.obolibrary.org/obo/>
PREFIX qudt: <http://qudt.org/schema/qudt/>

CONSTRUCT {
  # Quality typed with TTO class, linked to component
  ex:PLACEHOLDER_tensile_strength a tto:TTO_0000053 ;
    obo:RO_0000052 ex:PLACEHOLDER_material ;
    obo:IAO_0000417 ex:PLACEHOLDER_tensile_strength_svs .

  ex:PLACEHOLDER_tensile_strength_svs a obo:OBI_0001931 ;
    obo:OBI_0001938 ex:PLACEHOLDER_tensile_strength_value .

  ex:PLACEHOLDER_tensile_strength_value a qudt:QuantityValue ;
    qudt:unit qudt:MegaPA ;
    qudt:numericValue ?tensileStrengthValueFinal .
}
WHERE {
  /* AAS semanticId → TTO quality class mapping */
  ?tensileStrengthKey ns2:value
    "https://admin-shell.io/idta/...TensileStrengthMean/1/0" .
}
Both paths output PMDCO quality individuals with QUDT-typed values. The schemas disappear; the shared ontology remains.

Assembly Graph — Institutional Knowledge

The assembly graph (tension_pully.ttl) is company/institutional knowledge — it describes how the tension pulley is composed of its two parts, linking to assets in each dataspace via BFO (Basic Formal Ontology) part-whole relations.

@prefix pmdco: <https://w3id.org/pmd/co/> .
@prefix obo:   <http://purl.obolibrary.org/obo/> .
@prefix ex:    <http://example.org/assembly/> .

# === Tension Pulley Assembly ===
ex:TensionPulley_001
    a pmdco:Object ;
    rdfs:label "Tension Pulley Assembly"@en ;
    obo:BFO_0000051
      <https://catena-x.net/edc/assets/urn:uuid:3f5a8c2d-…> ,
      <https://mfg-x.2024.2de/dsp/assets/component-87654321> .

# === Part 1: Pulley Wheel (Catena-X Asset) ===
<https://catena-x.net/edc/assets/urn:uuid:3f5a8c2d-…>
    a pmdco:Object ;
    rdfs:label "Pulley Wheel"@en ;
    obo:BFO_0000050 ex:TensionPulley_001 ;
    obo:BFO_0000051 <…/material_data_test_pa6gf30-joined.ttl
                     #MaterialData_Z1234-material> .

# === Part 2: Tensioner Bracket (Manufacturing-X Asset) ===
<https://mfg-x.2024.2de/dsp/assets/component-87654321>
    a pmdco:Object ;
    rdfs:label "Tensioner Bracket"@en ;
    obo:BFO_0000050 ex:TensionPulley_001 ;
    obo:BFO_0000051 <http://www.example.org/#316-4401_material> .
This is the semantic glue at the institutional level. The graph knows what the assembly is made of — without caring which dataspace each part came from.

Unified Knowledge Graph in Fuseki

All three graphs are loaded into named graphs in a shared Fuseki triplestore; from this point the data is jointly queryable via SPARQL regardless of its origin schema.

Named graphs loaded: <catena-x> PA6GF30 material (PMDCO) <manufacturing-x> Steel 316/4401 (PMDCO) <assembly> Tension Pulley assembly Total: ~500 triples across 3 graphs SPARQL endpoint: dataportal.material-digital.de/…/fuseki/$/sparql
The three graphs are kept separate (named graphs) but are queryable together. The original source schemas are no longer relevant — only the PMDCO alignment matters.

Cross-Dataspace Query — SPARQL UNION

A single SPARQL SELECT with UNION handles the two different PMDCO graph patterns — one for Catena-X (material node → quality → datum → quantityValue) and one for Manufacturing-X (quality directly on component); this is the query that could not exist without a shared ontology.

SELECT ?componentLabel
       (COALESCE(?materialLabel, ?componentLabel) AS ?material)
       ?property ?value ?unitLabel
WHERE {
  ex:TensionPulley_001 obo:BFO_0000051 ?component .
  ?component rdfs:label ?componentLabel .

  {
    # Structure A: separate material entity (Catena-X)
    ?component obo:BFO_0000051 ?mat .
    ?mat rdfs:label ?materialLabel .
    ?mat obo:RO_0000086 ?quality .
    ?quality obo:IAO_0000417 ?datum .
    ?datum obo:OBI_0001938 ?qv .
    ?qv qudt:numericValue ?value .
    OPTIONAL { ?qv qudt:unit ?unit }
    BIND(STRAFTER(STR(?unit), "unit/") AS ?unitLabel)
  }
  UNION
  {
    # Structure B: qualities directly on component (MfgX/AAS2KG)
    ?component obo:RO_0000086 ?quality .
    ?quality obo:OBI_0001938 ?qv .
    ?qv pmd:PMD_0000006 ?value .
    OPTIONAL { ?qv obo:IAO_0000039 ?unit }
    BIND(STRAFTER(STR(?unit), "qudt/") AS ?unitLabel)
  }
  /* label resolution + FILTER omitted for brevity */
}
ORDER BY ?componentLabel ?property
